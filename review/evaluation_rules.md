# 的中判定ルール 確定案（P0-1）

対象: `predictions/` の各予想レコード。
目的: 誰が実行しても同じ判定になるよう、価格・期間・判定条件をすべて機械的に決める。

---

## 1. 基本方針

1. **超過リターン（対ベンチマーク）で判定する。** 絶対リターンだと上昇相場の「全部long」が高得点になるため（HANDOFF §7-5 への回答）。
2. **エントリー価格は投稿者の申告値ではなく、投稿後に最初に約定可能だった価格**を使う。投稿者の「株価7560円」は検証用の参考値。
3. **判定は終値ベース。** ザラ場高値の一瞬のタッチは `target_touched_intraday` として別記録し、スコアには使わない。
4. **削除された投稿も評価を続ける。** 削除は「外れ隠し」の主要経路なので、収集時点のスナップショットで評価する。
5. **期間が読み取れない予想はメインスコアに入れない**（§3.3）。

---

## 2. 価格の決め方

### 2.1 エントリー（t0）

| 投稿時刻（現地取引所時間） | エントリー価格 |
|---|---|
| 取引日の寄り付き前 | その日の始値 |
| 取引時間中・引け後・休場日 | **次の取引日の始値** |

- 日足データだけで再現でき、先読み（look-ahead）が起きない。
- 例: `@JNR63_nolife` の投稿は 2026-10-12（月）23:31 JST。10/12 はスポーツの日で東証休場 → エントリーは **10/13（火）の始値**。
- 投稿者申告の現値（`stated_price_at_post`）とエントリー価格が **±3% 以上ずれる場合は `price_mismatch` フラグ**を立てる（誤記・古い価格・別銘柄の疑い）。

### 2.2 エグジット（t1）

時間軸を**営業日数**に換算し、t0 から数えた最終営業日の**終値**を使う。

| `time_horizon` | 評価期間 | 備考 |
|---|---|---|
| `1d` | 1営業日 | 「明日注目」など。現スキーマにないので追加 |
| `this_week` | 投稿後最初の取引週の金曜終値 | 「今週」。週末投稿なら翌週。祝日で営業日数が減っても金曜（最終営業日）まで |
| `1w` | 5営業日 | 「1週間」など期間が明示されたもの |
| `2w` | 10営業日 | |
| `1m` | 21営業日 | |
| `3m` | 63営業日 | |
| `6m` | 126営業日 | 追加 |
| `1y` | 252営業日 | 追加 |
| `earnings` | 次回決算発表を織り込んだ最初の終値 | 引け後発表なら翌営業日終値。発表日が63営業日超先なら `3m` 扱い |
| `target_only` | 63営業日（上限） | 目標株価だけで期間なし。§3.3 参照 |
| （期間も目標もない long/short） | — | v2 では記録しない（`predictions/schema.md` §1） |

### 2.3 ベンチマーク

| 市場 | 既定ベンチマーク | Yahoo Finance シンボル |
|---|---|---|
| JP プライム/スタンダード | TOPIX連動ETF | `1306.T` |
| JP グロース | 東証グロース市場250 ETF | `2516.T` |
| US | S&P 500 ETF | `SPY` |

- 小型株を TOPIX と比べると、小型株ファクターの上下がそのまま的中/外れに出る。グロース市場の銘柄はグロース指数と比べる。
- 余力があれば補助指標としてセクターETF比（例: 半導体なら `SMH` / `2644.T`）も記録する。ただしランキングには使わない。

### 2.4 価格データの取得方法（提案、実装は別）

| 用途 | 第一候補 | 代替 |
|---|---|---|
| JP 日足（調整後） | `yfinance`（`5803.T`, `285A.T` 形式） | J-Quants API（JPX公式。無料プランは12週遅延なので、即時評価には有料プランが必要） / Stooq |
| US 日足（調整後） | `yfinance` | Stooq, Alpha Vantage, Polygon |
| JP 決算発表日 | J-Quants `fins/announcement` / TDnet | 各社IR |
| US 決算発表日 | yfinance `earnings_dates` | Nasdaq earnings calendar |
| 取引所カレンダー | `exchange_calendars`（`XTKS`, `XNYS`） | `pandas_market_calendars` |

- **分割・配当調整済みの終値**を使う（分割で「急落」と誤判定しないため）。
- yfinance は非公式APIで規約上の制約があるため、公開ランキングに使うなら J-Quants や有償データへの切り替えを検討する。
- 取得した価格は `prices/` に日付つきでキャッシュし、**評価をやり直しても同じ結果になる**ようにする（データ提供元の事後修正対策）。

## 3. 判定条件

記号:
- `r` = t0→t1 の銘柄リターン、`r_b` = 同期間のベンチマークリターン
- `r_ex = r − r_b`（超過リターン）
- `σ_h` = t0 直前60営業日の日次リターン標準偏差 × √(評価営業日数)。その銘柄にとって「その期間で普通に動く幅」
- `θ = max(0.5%, 0.25 × σ_h)` = 方向判定の不感帯（ノイズで決着させない）
- `dir` = long なら +1、short / avoid なら −1

### 3.1 方向のみの予想（long / short）

| 条件（t1 時点） | status |
|---|---|
| `dir × r_ex ≥ +θ` | `hit` |
| `dir × r_ex ≤ −θ` | `miss` |
| それ以外 | `flat`（引き分け。的中率の分母から除き、zスコアには含める） |

### 3.2 avoid（「買わなくていい」「様子見」）

- **short ではない。** 「買わんでいい」は「空売りしろ」ではないため、新しい `direction: avoid` を作る。
- 判定は short と同じ `dir = −1` で、超過リターンだけを見る（ベンチマークに劣後すれば hit）。
- 期間が書かれていない avoid は既定 `1m`（`horizon_source: default`）。
- ただし重みは 0.5（§スコアリング参照）。根拠: 逆張りの主張としては弱く、多くの銘柄が指数に劣後するという基準率の影響を受けやすい。

### 3.3 目標株価つきの予想

1. **方向判定**は §3.1 と同じ（目標価格の方向を `dir` にする）。
2. **目標到達判定**: 評価期間内のいずれかの終値が目標以上（short は以下）なら `target_reached = true`。
   - 到達した日を `target_reached_at` に記録し、その日で評価を打ち切ってよい（その日の終値で `r_ex` を確定）。
3. **進捗率** `progress = (P_t1 − P_t0) / (target − P_t0)` を [−1, 1] にクリップして記録する。
4. 期間なし（`target_only`）: 63営業日で打ち切る。これをしないと「いつか当たる」予想が永久に `open` のまま残り、外れにならない。
5. 物理的に到達できない目標（例: 日本株の値幅制限を超える1日目標）は抽出段階で `implausible_target` フラグを付ける。判定はそのまま行う（外れとして数える）。

### 3.4 条件付き予想（「60円以下は無条件で買い」など）

- `entry_condition` を記録し、**条件が満たされた日の終値**を t0 とする。
- 63営業日以内に条件が満たされなければ `void`（スコア対象外）。

### 3.5 neutral

- 「横ばい」「レンジ」など。`|r_ex| < θ` で hit。現スキーマの neutral は定義がないので、レンジ（上限・下限）を明示したものに限る。

## 4. status の再定義

現行の `open | hit | miss | expired` は「expired = 外れ」なのか「評価不能」なのかが曖昧。以下に置き換える。

| status | 意味 | スコア |
|---|---|---|
| `open` | 評価期間中 | 対象外 |
| `hit` | §3 の条件で的中 | 対象 |
| `miss` | §3 の条件で外れ | 対象 |
| `flat` | 不感帯内（引き分け） | zスコアのみ対象 |
| `void` | 評価不能（データ欠損、上場廃止で価格なし、条件未達など）。理由を `void_reason` に記録 | 対象外 |

- 旧 `expired` の扱い: 目標未到達で期間切れ → **`miss`（`target_reached=false`）** に統一する。「期間切れ」は status ではなく `evaluated_at` と `target_reached` で表す。
- **void の乱用防止**: 投稿削除・アカウント鍵化・アカウント削除は void にしない（スナップショットで評価を続ける）。
- TOB・合併で上場廃止になった場合: 最終売買日の終値で評価し、`corporate_action` を記録する。

---

## 5. 重複・連投の扱い

- 同一作者・同一銘柄・同一方向の予想が、先行予想の評価期間中に再投稿された場合は**新規予想にしない**。先行レコードの `reiterations` を +1 する。
  - 理由: 同じ主張の連投で件数（＝信頼度）が水増しされるのを防ぐ。
- 期間中に逆方向へ意見を変えた場合: 先行予想をその日の終値で打ち切り（`closed_by_author`）、新規予想を作る。
- 1投稿に複数銘柄がある場合は銘柄ごとにレコードを作るが、`post_ticker_count` を記録し、スコアでは投稿単位に按分する（scoring.md §2）。

---

## 6. 先読み・後知恵の防止

| リスク | 対策 |
|---|---|
| 抽出者（Grok）が値動きを知った後に、当たった投稿だけを拾う | 投稿から **36時間以内**に収集・抽出されたものだけをメインスコアに入れる。それ以降に拾った分は `backfill: true` として参考扱い |
| 収集前に外れ投稿が削除される | 収集頻度（JP 08:00 / US 22:00）で取りこぼすのは避けられない。`collected_at` を必ず記録し、収集ラグの分布を月次レポートに載せる |
| 作者の事後編集 | X の編集は投稿後1時間以内に限られる。編集履歴がある場合は**最初のバージョン**で抽出する |
| 候補選定の時点で「最近当たった人」を選んでいる | **候補リストに追加された日（`added_at`）以降の投稿だけ**を数える（前向き評価） |

## 7. 擬似コード

```python
def evaluate(pred, prices, bench, cal):
    t0 = first_tradable_open(pred.posted_at, cal)          # §2.1
    if pred.entry_condition:
        t0 = first_close_meeting(pred.entry_condition, after=t0, within=63) or VOID
    t1 = horizon_end(t0, pred.time_horizon, pred.ticker, cal)  # §2.2
    if t1 is None:
        return VOID("no horizon")  # v2 では抽出段階で除外済みのはず
    if today < t1:
        return OPEN

    p0, b0 = prices.open[t0], bench.open[t0]
    hit_day = None
    if pred.target_price:
        hit_day = first_close_crossing(prices, pred.target_price, t0, t1, pred.dir)
        if hit_day:
            t1 = hit_day
    r    = prices.close[t1] / p0 - 1
    r_b  = bench.close[t1] / b0 - 1
    r_ex = r - r_b
    sigma_h = prices.daily_ret_std(lookback=60, before=t0) * sqrt(trading_days(t0, t1))
    theta = max(0.005, 0.25 * sigma_h)
    z = clip(pred.dir * r_ex / sigma_h, -3, 3)

    s = pred.dir * r_ex
    status = "hit" if s >= theta else "miss" if s <= -theta else "flat"
    return Result(status, r, r_b, r_ex, sigma_h, z, target_reached=bool(hit_day))
```
